# Fix `turbo` not found in dobeu-design-system

## Context

`pnpm publish-packages` fails at the first step with:

```
'turbo' is not recognized as an internal or external command
```

The assumption was that this related to a recently-set token variable. It does not.
Investigation shows two independent issues that happen to be in the same repo:

1. **The build failure**: `node_modules/` does not exist in
   `C:\Users\JeremyWilliams\repos\dobeu-design-system`. Dependencies were never
   installed (or were wiped). pnpm resolves script binaries from
   `node_modules/.bin`, so `turbo` — declared as a root devDependency and pinned to
   `2.9.7` in the lockfile — has no binary on disk. `turbo` is also not on PATH
   globally, so nothing else can satisfy it.

2. **A dead variable, unrelated to the failure**: `.env` contains
   `FIGMA_NPM_TOKEN=figp_…`. Nothing consumes that name:
   - No `.npmrc` in the repo; `~/.npmrc` has a literal `_authToken` and never
     references `${FIGMA_NPM_TOKEN}`.
   - `@figma/code-connect` is a **public** npm package — installing it needs no auth.
   - `figp_` is Figma's *personal access token* prefix, not an npm token.
   - The repo's own script reads a **different** name — `FIGMA_ACCESS_TOKEN`
     (`packages/components-react/scripts/figma-resolve-code-connect-nodes.mjs:17`),
     matching `docs/figma-pro-library-setup.md:53`.
   - `.env` isn't loaded by anything in this repo (no `dotenv` dependency), so even
     the correct name in that file won't reach a process automatically.

   The token *value* is the right kind of credential; only the key name is wrong,
   and it is needed for the Code Connect node-resolution workflow — never for install
   or build.

Outcome: `pnpm build` / `pnpm publish-packages` run to completion, and the Figma
token is stored under the name the repo actually reads.

## Fix

### 1. Install dependencies (this is the actual fix)

```powershell
cd C:\Users\JeremyWilliams\repos\dobeu-design-system
pnpm install --frozen-lockfile
```

The lockfile (`lockfileVersion: '9.0'`) is current — its `importers` already cover
the root, `packages/tokens`, and `packages/components-react`, so a frozen install
should succeed with no lockfile churn.

Fallbacks if it does not:
- **Lockfile-out-of-date error** → drop `--frozen-lockfile` and run plain
  `pnpm install`, then review the `pnpm-lock.yaml` diff before committing.
- **HTTP 401/403 on registry fetches** → the literal `_authToken` for
  `registry.npmjs.org` in `~/.npmrc` is stale. Re-auth with `npm login`, or comment
  that line out (public packages need no token).
- **"Ignored build scripts" warning** (pnpm 10 blocks postinstall by default; esbuild
  under vitest wants one) → `pnpm approve-builds`. Not required for `turbo build`,
  but needed before `pnpm test` works.

### 2. Rename the Figma variable in `.env`

Edit `C:\Users\JeremyWilliams\repos\dobeu-design-system\.env` — change the key only,
keep the `figp_…` value:

```diff
-FIGMA_NPM_TOKEN=figp_…
+FIGMA_ACCESS_TOKEN=figp_…
```

`.env` is already covered by `.gitignore`, so the secret stays out of git.

Because nothing auto-loads `.env`, the Code Connect script must be invoked with the
value passed explicitly. Document this in `docs/figma-pro-library-setup.md` next to
the existing line 53 reference:

```powershell
$env:FIGMA_ACCESS_TOKEN = (Get-Content .env | Select-String '^FIGMA_ACCESS_TOKEN=').ToString().Split('=',2)[1]
pnpm --filter @dobeu/components-react figma:resolve-nodes
```

## Known non-blocker: `changeset publish` will be a no-op

`publish-packages` is `turbo build && changeset publish`. Both `@dobeu/tokens` and
`@dobeu/components-react` are `"private": true`, so changesets will skip them and
publish nothing — the two pending changesets in `.changeset/` stay unconsumed. This
is expected for now and is **not** an error to chase. When you are ready to release,
that requires: removing `private: true`, confirming the `@dobeu` npm scope is owned
and authenticated, and running `changeset version` before `changeset publish`.

## Files touched

- `.env` — rename `FIGMA_NPM_TOKEN` → `FIGMA_ACCESS_TOKEN` (value unchanged)
- `docs/figma-pro-library-setup.md` — add the explicit token-passing invocation
- `node_modules/`, possibly `pnpm-lock.yaml` — generated by install, not hand-edited

No source, `turbo.json`, or `package.json` changes are needed.
